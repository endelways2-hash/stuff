## 1. Что заменить

В `_v3_build_model` сейчас положительное направление определения `hit` записано так:

```python
model.add(before == b).only_enforce_if(hit)
```

Заменить его на:

```python
_v2_add_mux(model, hit, b, before, b)
```

Это записывает ограничение

\[
b=[b,\ before]_{hit}.
\]

По определению `Element`, выбранная индексом величина должна быть равна target. Поэтому: ([raw.githubusercontent.com](https://raw.githubusercontent.com/google/or-tools/v9.15/ortools/sat/python/cp_model.py))

- `hit = 0`: получаем `b = b`, то есть никаких дополнительных требований;
- `hit = 1`: получаем `before = b`.

Таким образом,

\[
(hit=1\Rightarrow before=b)
\quad\Longleftrightarrow\quad
Element(hit,[b,before],b).
\]

**Не удаляется ни одно направление определения `hit`.** Все остальные ограничения v3 остаются без изменений.

### Почему показатели не растут

У заменяемого ограничения и у нового ограничения один и тот же набор переменных:

\[
\{hit,\ before,\ b\}.
\]

Повторение `b` в массиве и в target **не добавляет переменную и не увеличивает арность**, если считать различные ссылки, как в вашем измерителе.

На одну замену:

| Показатель | Было | Стало |
|---|---:|---:|
| Переменные | те же | те же |
| Ограничения | 1 | 1 |
| Арность | 3 | 3 |
| Явные коэффициенты | 2 | 0 |
| Концы линейного домена | 2 | 0 |

**Здесь принципиально использовать `_v2_add_mux`, который записывает компактный legacy `Element`.** Обычный `model.add_element(...)` с новым форматом линейных выражений не обеспечивает этой экономии коэффициентов. В protobuf OR-Tools 9.15 оба формата предусмотрены; смешивать их нельзя. ([raw.githubusercontent.com](https://raw.githubusercontent.com/google/or-tools/v9.15/ortools/sat/cp_model.proto))

## 3. Доказательство на Lean

Сохраните как `GuardElement.lean`.

Доказательство охватывает:
1. локальную замену;
2. её применение к произвольному числу ограничений в произвольной остальной модели;
3. сохранение любых проекций решений — например, начальной колоды и выходной трассы;
4. численные неравенства из таблицы.

Здесь `rest` содержит **всю неизменяемую часть модели**, включая окна, modulo, исходные ограничения различности и остальные связи.

```lean
import Lean

namespace GuardElement

-- hit : Bool точно представляет существующую переменную
-- с доменом {0, 1}. Новая переменная не вводится.
def Element2 {α : Type}
    (hit : Bool) (lo hi target : α) : Prop :=
  (if hit = true then hi else lo) = target

-- Локальная эквивалентность.
theorem guard_iff_element {α : Type}
    (hit : Bool) (before b : α) :
    (hit = true → before = b) ↔
      Element2 hit b before b := by
  cases hit <;> simp [Element2]

variable {State Index : Type}

-- Полное присваивание всем переменным представлено State.
-- Index перечисляет заменяемые ограничения.
def Model3
    (rest : State → Prop)
    (hit : State → Index → Bool)
    (before b : State → Index → Int)
    (s : State) : Prop :=
  rest s ∧
    ∀ i, hit s i = true → before s i = b s i

def Model4
    (rest : State → Prop)
    (hit : State → Index → Bool)
    (before b : State → Index → Int)
    (s : State) : Prop :=
  rest s ∧
    ∀ i, Element2 (hit s i) (b s i) (before s i) (b s i)

-- Совпадают все полные присваивания, а не только SAT/UNSAT.
theorem models_equivalent
    (rest : State → Prop)
    (hit : State → Index → Bool)
    (before b : State → Index → Int)
    (s : State) :
    Model3 rest hit before b s ↔
      Model4 rest hit before b s := by
  simp only [Model3, Model4, guard_iff_element]

-- Сохраняются любые наблюдаемые результаты.
theorem same_projection {Output : Type}
    (rest : State → Prop)
    (hit : State → Index → Bool)
    (before b : State → Index → Int)
    (observe : State → Output)
    (output : Output) :
    (∃ s, Model3 rest hit before b s ∧ observe s = output) ↔
      (∃ s, Model4 rest hit before b s ∧ observe s = output) := by
  constructor
  · intro h
    rcases h with ⟨s, hs, hout⟩
    exact ⟨s, (models_equivalent rest hit before b s).mp hs, hout⟩
  · intro h
    rcases h with ⟨s, hs, hout⟩
    exact ⟨s, (models_equivalent rest hit before b s).mpr hs, hout⟩

structure Metrics where
  variables : Nat
  constraints : Nat
  totalArity : Nat
  maxArity : Nat
  coefficientEntries : Nat
  maxCoefficient : Nat
  rhsEndpoints : Nat

def NoGrowth (old new : Metrics) : Prop :=
  new.variables ≤ old.variables ∧
  new.constraints ≤ old.constraints ∧
  new.totalArity ≤ old.totalArity ∧
  new.maxArity ≤ old.maxArity ∧
  new.coefficientEntries ≤ old.coefficientEntries ∧
  new.maxCoefficient ≤ old.maxCoefficient ∧
  new.rhsEndpoints ≤ old.rhsEndpoints

def csv3 : Metrics where
  variables := 83 + 1027 + 39287 + 39287
  constraints := 1027 + 39287 + 39287 + 13095 + 861
  totalArity := 2 * 1027 + 4 * 39287 + 3 * 39287
    + 38260 + 13095 + 3403
  maxArity := 4
  coefficientEntries := 2 * 1027 + 2 * 39287
    + 38260 + 13095 + 3403
  maxCoefficient := 1
  rhsEndpoints := 2 * 39287

def csv4 : Metrics :=
  { csv3 with
    coefficientEntries := 2 * 1027 + 38260 + 13095 + 3403
    rhsEndpoints := 0 }

theorem csv_goal :
    NoGrowth csv3 csv4 ∧
    2 * csv4.coefficientEntries ≤ csv3.coefficientEntries ∧
    2 * csv4.rhsEndpoints ≤ csv3.rhsEndpoints := by
  decide
```
